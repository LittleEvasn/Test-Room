# Witchlings VFX Lab — 별빛탄 + 꽃폭탄 + 달빛 부메랑 + 블랙홀 + 가시꽃 덫

Godot 4.6 / GL Compatibility 독립형 마법 VFX 실험실입니다. **본게임 `witchlings-mayhem`에는 영향을 주지 않습니다.**

## 실행

1. GitHub Desktop에서 `Test-Room` 저장소를 선택해 `Fetch origin` → `Pull origin`을 진행합니다.
2. **Repository → Show in Explorer**로 로컬 저장소 폴더를 엽니다.
3. Godot 프로젝트 관리자에서 그 폴더의 `project.godot`을 가져오고 **F5**로 실행합니다.
4. 이미 Godot에 열려 있다면 파일 동기화가 끝난 뒤 프로젝트를 다시 열어 확인합니다.

## 조작

| 입력 | 기능 |
| --- | --- |
| `1` | 별빛탄 선택 (기존 VFX 유지) |
| `2` | 꽃폭탄 선택 |
| `3` | 달빛 부메랑 선택 (호형 출격 → 표적 타격 → 반대쪽 곡선으로 귀환) |
| `4` | 소용돌이 씨앗의 블랙홀 VFX 선택 (5초간 이동·흡입 시각 효과·성장·소멸) |
| `5` | **가시꽃 덫** 선택 — 투척 씨앗 → 굴림·튐 → 팍! 전개 → 설치 대기 |
| `Q / E` | 선택한 마법의 +0~+3 시각 강화 비교 (꽃폭탄·블랙홀·가시꽃 덫) |
| `T` | **가시꽃 덫 전용:** 표적 위치에 가장 가까운 **설치 완료된 덫** 1개를 가상 발동 (적 접근 시뮬레이션) |
| 마우스 왼쪽 클릭 | 표적 위치 변경 + 발사 |
| 마우스 오른쪽 클릭 / `Space` | 선택한 마법 발사 |
| `R` | 자동 발사 켜기/끄기 |
| `↑ / ↓` | 파티클 밀도 0~3배 조절 |
| `C` | 투사체 정리 및 통계 초기화 (남은 폭발은 자연 소멸) |

## 꽃폭탄 VFX 설계

비행 중 꽃탄 이미지가 천천히 회전하며 사용자가 그린 꽃잎과 빛점이 뒤에 남습니다. 표적에 닿거나 수명이 끝나면 꽃잎 다섯 장이 72도 간격으로 더 크게 펼쳐지고, 확대된 **실험실 폭발 반경까지 굵은 충격파 링**이 퍼집니다. 주변 파편도 다섯 방향으로 흩어집니다. 떨어져 나온 파편은 독립적으로 흩날리다가 사라집니다. `bloom_burst.gd`는 게임의 피해 처리와 무관한 시각 효과입니다.

**꽃폭탄 폭발 반경 90/115/145/180은 VFX 실험실 전용 설정입니다. 본게임 반경 70/90/115/140은 아직 변경하지 않았습니다.**

이 실험실은 실제 적 충돌 대신 **표적 도착 또는 수명 종료**를 폭발 사건으로 사용합니다. 본게임 통합 시에는 기존 꽃폭탄의 실제 `behavior.area` 명중/만료 사건에 VFX를 연결해야 하며, 화면상의 링과 실제 판정 반경이 일치하는지 검증해야 합니다.

## 달빛 부메랑 테스트

- `3`번을 눌러 달빛 부메랑을 선택합니다. 자동 발사 또는 `Space`/클릭으로 즉시 발사할 수 있습니다.
- 사용자의 초승달 PNG가 회전하며 **호를 그려 표적에 도착**합니다. 표적에서는 베기 섬광이 발생하지만, 달은 사라지지 않고 **반대편 곡선을 따라 출발점으로 복귀**합니다.
- 초승달의 반투명 잔상과 보랏빛 파티클이 이동 궤적을 드러냅니다. 출발점으로 돌아오면 짧은 회수 섬광이 발생합니다.
- 이번 실험실에는 실제 적, 도탄 후보 및 충돌 판정이 없으므로 **표적 1회 타격 후 회수**만 테스트합니다. 본게임의 +1~+3 도탄/재표적 동작과는 구분합니다.
- 이 코드는 본게임을 수정하지 않습니다. 실제 전투에 이식할 때에는 기존 달빛 부메랑의 호형 비행, 도탄 소진, 이동하는 플레이어를 향한 귀환과 연결해야 합니다.

## 소용돌이 씨앗 → 블랙홀 VFX 테스트

- `4`번을 눌러 블랙홀을 선택한 다음 `Space`나 마우스로 생성합니다. 자동 발사는 약 5.2초 간격이며 **기존 블랙홀이 살아 있는 동안 새 블랙홀을 자동으로 겹쳐 놓지 않습니다**. 수동 입력은 기존 블랙홀을 교체해 새 조준점에서 다시 생성합니다.
- 블랙홀은 표적 지점에서 생성되어 **5초 동안 천천히 이동**합니다. 2026-10-31 v4에서는 사용자 실제 게임 화면을 기준으로 **성숙한 최종형 원반을 생성 순간부터 동일한 형태로 표시**하도록 변경했습니다. 시작할 때 반경을 조여 흐릿한 도넛이 나타나던 문제를 없애고 약 0.11초의 밝기 페이드만 적용합니다. 원반은 진보라/자주 계열로 변경했으며, 내부는 바깥보다 훨씬 빠르게 회전합니다. 외곽 질감과 밝기는 비대칭으로 흔들리고 중심은 검은 공간과 밝은 연보라색 테두리를 유지합니다. 별도 PNG는 필요 없습니다.
- **2종류의 보라색 작은 입자(빛 점·짧은 선)**가 월드 좌표를 유지하면서 블랙홀 중심으로 나선형 흡입됩니다. 본체 질감과 별개로 그려져 중심으로 빨려 들어가는 동작이 보입니다.
- `Q/E`로 성장 실험 단계를 `+0/+1/+2/+3` 조절합니다. **+0은 성장하지 않습니다.** 나머지 성장 계수 0.07/0.14/0.21은 VFX 모의값으로, 본게임 수치로 확정된 값이 아닙니다.
- 0.25초마다 **가상의 범위 피해 틱 신호**를 내고 HUD의 `가상 틱` 수에 누적합니다. 주변 적을 실제로 끌어오거나 피해를 주는 코드는 포함하지 않습니다.
- 중첩/병합/합체에 따른 성장 코드는 없습니다. Test-Room은 **시각 검토를 위해 한 번에 한 개만 표시**합니다. 수동 재생성은 이전 개체를 교체합니다. 이 UI 정책은 본게임의 미확정 중복 배치 규칙과는 별개입니다.
- 끝날 때 약 0.40초에 걸쳐 셰이더 원반과 중심핵이 함께 축소·소멸합니다. **본게임의 `vortex` 공격/판정/성장/강화 코드는 건드리지 않았습니다.**
- 관련 확정 설계: 본게임 `docs/ai-workspace/decisions/2026-10-30-vortex-magicraft-black-hole-replacement.md`. 그 보고서는 블랙홀 이동·흡입·틱 피해·시간 성장의 실제 게임 코드 이식은 미완료라고 명시합니다.

### 블랙홀 v5: 검은 중심 반지름 축소

- 사용자 요청에 따라 **검은 중심핵 반지름과 라벤더색 중심 테두리를 이전 v4의 50%로 축소**했습니다.
- **바깥 보라색 원반의 외경·색상·회전 속도·노이즈 흐름·외곽의 불규칙한 일렁임은 변경하지 않았습니다.**
- 중심이 작아지면서 생기는 내부 빈 공간은 기존 원반의 움직이는 질감으로 채우고, 작은 흡입 입자는 새 중심 가까이까지 이동하도록 종료 위치만 변경했습니다.

## 가시꽃 덫 (Thorn) VFX 테스트

**본게임 확정 설계:** [괴이한 지뢰식 가시꽃 덫 전개 보고서](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/docs/ai-workspace/reports/2026-10-30-thorn-trap-magicraft-deceptive-mine-deployment.md).

1. `5`번 선택 후 `Space` 또는 클릭: **사용자 원본 `가시꽃 탄.png`** 씨앗 투척.
2. 씨앗은 **마법공예 괴이한 지뢰(Spell1012TrickMine)** 참고 물리로 약 1.55초 동안 운동·정지 후 설치한다. 원작 분석값인 시작 속도 8, 중력 15, 초기 수직속도 -4, 바닥 반발 0.33, 회전 15도/초를 화면 좌표계에 맞춰 변환했다. **마우스 클릭은 투척 방향을 정하고 착지점은 속도·중력·마찰로 결정**된다(목표 위치 강제 이동·순간이동 없음). 첫 충돌 뒤 반발·회전·수평 운동이 함께 줄어들며, 튐 높이는 가독성을 위해 낮게 표시한다.
**씨앗 크기:** 업로드된 512×512 PNG의 실제 불투명 영역을 기준으로 측정한 결과 씨앗 폭은 123px, 심지 폭은 118px이다. 강화별 설치 반경을 동일하게 적용한 뒤 씨앗이 보이는 심지의 약 **88%**가 되도록 비례 축소했다(+0 기준 씨앗 약 28px / 심지 약 33px). 기존 씨앗은 약 66px로 너무 컸다.

3. 착지 시 약 0.26초 동안 **`가시꽃 줄기.png` ×5 + `가시꽃 잎.png` ×5 + `가시꽃 심지.png`**가 중심에서 일제히 팍 펼쳐진다. 이는 공격 피해가 아니라 **설치 단계**다.
4. 전개 완료 후 **`가시꽃 완성본.png`**로 대기한다. `T`를 누르면 표적 위치에 가장 가까운 무장된 덫 1개가 가상 발동하며 팔이 오므라들고 파동이 나온 뒤 사라진다. `T`를 누르지 않으면 설치 수명이 끝나고 소멸한다.
5. `Q/E`로 **반경 62/80/100/125px**, 설치 대기시간 **6/7/8/9초**를 비교. 여러 덫을 연속 생성하여 설치된 덫들의 독립 동작을 확인할 수 있다(실험실 안전상 동시 최대 12개).

**굴림 복원(2026-10-31):** 처음 참조한 **15도/초는 원작 이펙트 회전 계수**로, 바닥을 굴러가는 씨앗의 회전까지 그 수치로 제한해서는 안 됐다. 또한 바닥 반발 **0.33은 수직 반발 계수**인데 이전 테스트에서는 수평 이동속도까지 똑같이 감소시키고 마지막 접촉 때 속도를 0으로 만들어 굴림이 사라졌다. 이제 **공중 투척 → 1회 감쇠 바운스 → 별도 지면 굴림 → 지수 마찰 감속 → 전개**로 분리했다. 지면 굴림에서는 씨앗이 이동한 거리와 크기에 맞춰 회전하며, 시각 가독성을 위해 회전 각속도를 최대 10rad/s로 제한한다. 수평 충돌 유지율 0.82, 지면 마찰 3.8, 바운스 1회는 **원작 수치가 아닌 Test-Room 시각 조정값**이다. 60FPS 계산 예시에서 지면 굴림 약 0.83초, 추가 이동 약 87px, 회전 약 240도로 확인했다. **씨앗 크기(심지의 88%) 및 설치·발동 VFX는 그대로 유지**한다.

**정확도 및 미확정 사항:** 운동은 Magicraft의 `Spell1012TrickMineSystem` 공개 역컴파일에서 확인한 **속도·중력·반발·회전 수치와 상태 변화**를 참고해 Godot 2D 화면용으로 구현한 실험 모델이다. Unity의 세계 단위→Godot 픽셀 단위 변환값(현재 실험실 64px/단위), 화면상 높이 축소, 1.55초 지연 등은 원작 확정 값이 아니다. 원작 ECS 물리 충돌/지형 검사를 완전히 이식한 것도 아니다. 원작 폭발 피해/연쇄 폭발은 의도적으로 제외. 현행 실험실에는 적이 없으므로 **T키를 적 접근 트리거로 대체**한다. 합성 `meteor_thorn` / `timed_thorn`의 본게임 로직이나 기존 `garden` 중첩·성장은 수정하지 않았다. 탄 이미지와 완성본의 중심을 맞추는 데 512x512 투명 캔버스 좌표를 그대로 사용하며, 초기 스프라이트들은 전부 교체 없이 원본을 참조한다.

## 파티클 표현 방식

- 기존 세 마법의 비행 및 타격 파티클은 공용 노란 `spark.png`에 의존하지 않고, Godot `Node2D._draw()`의 선/원/다각형과 원본 꽃잎 PNG를 조합합니다.
- 별빛탄: 금빛 글린트, 작은 빛 구슬, 방향성 광선 파편.
- 꽃폭탄: 사용자가 그린 꽃잎, 분홍 꽃가루, 복숭아색 마름모 반짝임, 짧은 빛줄기.
- 달빛 부메랑: 은백색 먼지, 보라색 마름모형 파편, 원호형 달빛, 글린트, 회전하는 초승달 잔상.
- 블랙홀: `ColorRect + ShaderMaterial`에서 **보라색 흐름·불규칙한 외곽·빠른 중심 회전·흰 라벤더 림**을 출력하고, `Node2D._draw()`는 보라색 흡입 입자에만 사용합니다. 생성 때는 크기·질감 구조를 유지하고 밝기만 빠르게 올라오며, 만료 시에만 전체가 수축합니다. 셰이더는 Godot GL Compatibility에서 동작을 확인할 필요가 있습니다.
- 기존 투사체 이동·5장 개화·꽃폭탄 테스트 폭발 반경 90/115/145/180·달빛 부메랑 귀환 구조는 유지합니다.
- `↑/↓` 파티클 밀도 조절은 계속 적용합니다. 입자 최대 개수는 각 마법별로 제한합니다.

## 검증 상태

- 별빛탄·꽃폭탄·달빛 부메랑·블랙홀 스크립트와 실험실 UI를 Godot 4.6 문법에 맞춰 작성함
- 기존 PNG와 프로젝트 구조를 그대로 재사용
- 셰이더 파일 연결과 GDScript의 신호/메서드 구조를 GitHub에서 확인함. 이 실행 환경에는 Godot 바이너리가 없어 **Godot 4.6(GL Compatibility)에서의 실제 셰이더 컴파일·시각 결과는 아직 확인하지 못함**
- 원본 PNG의 알파 경계가 깨끗한지, 초승달 회전·출격 및 귀환 속도와 파티클 양이 적정한지는 로컬 테스트 필요
