# Witchlings VFX Lab — 기본 공격 VFX 및 보조 실험실

Godot 4.6 / GL Compatibility 독립형 마법 VFX 실험실입니다. **본게임 `witchlings-mayhem`에는 영향을 주지 않습니다.**

## 실행

1. GitHub Desktop에서 `Test-Room` 저장소를 선택해 `Fetch origin` → `Pull origin`을 진행합니다.
2. **Repository → Show in Explorer**로 로컬 저장소 폴더를 엽니다.
3. Godot 프로젝트 관리자에서 그 폴더의 `project.godot`을 가져오고 **F5**로 실행합니다.
4. 이미 Godot에 열려 있다면 파일 동기화가 끝난 뒤 프로젝트를 다시 열어 확인합니다.

## 화면 크기 및 본게임과의 비교 기준

- 본게임 `LittleEvasn/witchlings-mayhem/project.godot`와 동일하게 **1600×900 내부 기준 해상도**, `canvas_items` 스트레치, **1920×1080 창 크기 지정**, `window/size/mode=3`(전체화면)으로 설정했습니다. 이전 Test-Room은 같은 내부 해상도를 **1280×720 창**에 축소 표시해 화면상 이펙트 크기를 혼동할 수 있었습니다.
- **이미 존재하던 `scripts/main.gd`의 1600×900 좌표계와 각 마법의 픽셀 크기·속도·시간·실제 효과 코드는 변경하지 않았습니다.** 게임과 테스트실 모두 같은 내부 좌표를 사용하기 때문입니다.
- 단, **본게임의 카메라 확대율은 전투 모드마다 다릅니다.** `scripts/game.gd`의 `set_arena_profile()`을 확인한 결과 일반 `scroll`은 `camera.zoom=0.8`, `trial`과 `measurement`는 `1.0`입니다. **Test-Room에는 카메라가 없어서 화면상 확대율 1.0**입니다. 따라서 이 변경으로 **해상도와 창 확대 비율은 일치**하지만, 일반 `scroll` 전투의 화면상 마법 크기까지 완전히 동일한 것은 아닙니다. 본게임 일반 전투와 1:1 시각 비교 시 카메라 줌도 따로 고려해야 합니다.
- Godot 실행 환경과 모니터 설정에 따라 전체화면의 실제 물리 픽셀은 운영체제 디스플레이 해상도를 따를 수 있습니다.

## 꽃폭탄 VFX 설계

비행 중 꽃탄 이미지가 천천히 회전하며 사용자가 그린 꽃잎과 빛점이 뒤에 남습니다. 표적에 닿거나 수명이 끝나면 꽃잎 다섯 장이 72도 간격으로 더 크게 펼쳐지고, 확대된 **실험실 폭발 반경까지 굵은 충격파 링**이 퍼집니다. 주변 파편도 다섯 방향으로 흩어집니다. 떨어져 나온 파편은 독립적으로 흩날리다가 사라집니다. `bloom_burst.gd`는 게임의 피해 처리와 무관한 시각 효과입니다.

**꽃폭탄 폭발 반경 90/115/145/180은 VFX 실험실 전용 설정입니다. 본게임 반경 70/90/115/140은 아직 변경하지 않았습니다.**

이 실험실은 실제 적 충돌 대신 **표적 도착 또는 수명 종료**를 폭발 사건으로 사용합니다. 본게임 통합 시에는 기존 꽃폭탄의 실제 `behavior.area` 명중/만료 사건에 VFX를 연결해야 하며, 화면상의 링과 실제 판정 반경이 일치하는지 검증해야 합니다.

## 달빛 부메랑 테스트

- `3`번을 눌러 달빛 부메랑을 선택합니다. 자동 발사 또는 `Space`/클릭으로 즉시 발사할 수 있습니다.
- 사용자의 초승달 PNG가 회전하며 **호를 그려 표적에 도착**합니다. 표적에서는 베기 섬광이 발생하지만, 달은 사라지지 않고 **반대편 곡선을 따라 출발점으로 복귀**합니다.
- 초승달의 반투명 잔상과 보랏빛 파티클이 이동 궤적을 드러냅니다. 출발점으로 돌아오면 짧은 회수 섬광이 발생합니다.
- 이번 실험실에는 실제 적, 도탄 후보 및 충돌 판정이 없으므로 **표적 1회 타격 후 회수**만 테스트합니다. 본게임의 +1~+3 도탄/재표적 동작과는 구분합니다.
- 이 코드는 본게임을 수정하지 않습니다. 실제 전투에 이식할 때에는 기존 달빛 부메랑의 호형 비행, 도탄 소진, 이동하는 플레이어를 향한 귀환과 연결해야 합니다.

## 소용돌이 씨앗 → 블랙홀 VFX 테스트

- `4`번을 눌러 블랙홀을 선택한 다음 `Space`나 마우스로 생성합니다. 자동 발사는 약 5.2초 간격이며 **기존 블랙홀이 살아 있는 동안 새 블랙홀을 자동으로 겹쳐 놓지 않습니다**. 수동 입력은 기존 블랙홀을 교체해 새 조준점에서 다시 생성합니다.
- 블랙홀은 표적 지점에서 생성되어 **5초 동안 천천히 이동**합니다. 2026-10-31 v4에서는 사용자 실제 게임 화면을 기준으로 **성숙한 최종형 원반을 생성 순간부터 동일한 형태로 표시**하도록 변경했습니다. 시작할 때 반경을 조여 흐릿한 도넛이 나타나던 문제를 없애고 약 0.11초의 밝기 페이드만 적용합니다. 원반은 진보라/자주 계열로 변경했으며, 내부는 바깥보다 훨씬 빠르게 회전합니다. 외곽 질감과 밝기는 비대칭으로 흔들리고 중심은 검은 공간과 밝은 연보라색 테두리를 유지합니다. 별도 PNG는 필요 없습니다.
- **2종류의 보라색 작은 입자(빛 점·짧은 선)**가 월드 좌표를 유지하면서 블랙홀 중심으로 나선형 흡입됩니다. 본체 질감과 별개로 그려져 중심으로 빨려 들어가는 동작이 보입니다.
- `Q/E`로 성장 실험 단계를 `+0/+1/+2/+3` 조절합니다. **+0은 성장하지 않습니다.** 나머지 성장 계수 0.07/0.14/0.21은 VFX 모의값으로, 본게임 수치로 확정된 값이 아닙니다.
- 0.25초마다 **가상의 범위 피해 틱 신호**를 내고 HUD의 `가상 틱` 수에 누적합니다. 주변 적을 실제로 끌어오거나 피해를 주는 코드는 포함하지 않습니다.
- 중첩/병합/합체에 따른 성장 코드는 없습니다. Test-Room은 **시각 검토를 위해 한 번에 한 개만 표시**합니다. 수동 재생성은 이전 개체를 교체합니다. 이 UI 정책은 본게임의 미확정 중복 배치 규칙과는 별개입니다.
- 끝날 때 약 0.40초에 걸쳐 셰이더 원반과 중심핵이 함께 축소·소멸합니다. **본게임의 `vortex` 공격/판정/성장/강화 코드는 건드리지 않았습니다.**
- 관련 확정 설계: 본게임 `docs/ai-workspace/decisions/2026-10-30-vortex-magicraft-black-hole-replacement.md`. 그 보고서는 블랙홀 이동·흡입·틱 피해·시간 성장의 실제 게임 코드 이식은 미완료라고 명시합니다.

### 블랙홀 v5: 검은 중심 반지름 축소

- 사용자 요청에 따라 **검은 중심핵 반지름과 라벤더색 중심 테두리를 이전 v4의 50%로 축소**했습니다.
- **바깥 보라색 원반의 외경·색상·회전 속도·노이즈 흐름·외곽의 불규칙한 일렁임은 변경하지 않았습니다.**
- 중심이 작아지면서 생기는 내부 빈 공간은 기존 원반의 움직이는 질감으로 채우고, 작은 흡입 입자는 새 중심 가까이까지 이동하도록 종료 위치만 변경했습니다.

## 가시꽃 덫 (Thorn) VFX 테스트

**본게임 확정 설계:** [괴이한 지뢰식 가시꽃 덫 전개 보고서](https://github.com/LittleEvasn/witchlings-mayhem/blob/main/docs/ai-workspace/reports/2026-10-30-thorn-trap-magicraft-deceptive-mine-deployment.md).

1. `5`번 선택 후 `Space` 또는 클릭: **사용자 원본 `가시꽃 탄.png`** 씨앗 투척.
2. 씨앗은 **마법공예 괴이한 지뢰(Spell1012TrickMine)**의 비낙하 지뢰 운동 분기를 참고한다. 기본 속도 8, 중력 15, 초기 수직속도 -4, 충돌 시 수직 속도 ×-0.528 및 수평·회전 속도 ×0.66을 적용하며, **회전 초기값은 원작의 ±15라디안/초**이다. Unity의 Y축 위쪽 화면과 Godot의 Y축 아래쪽 화면에서 시각적 회전 방향이 뒤집히므로 **Godot에서는 회전 부호를 반전**한다. 클릭한 위치는 발사 방향만 결정하고, 지뢰가 원작의 정지 조건(수직 속도 절댓값 또는 수평 속도 ≤0.2)에 도달했을 때 펼쳐진다. 바닥 마찰로 임의 감속하거나 1.55초에 강제로 펼치는 처리는 폐기했다.
**씨앗 크기:** 업로드된 512×512 PNG의 실제 불투명 영역을 기준으로 측정한 결과 씨앗 폭은 123px, 심지 폭은 118px이다. 강화별 설치 반경을 동일하게 적용한 뒤 씨앗이 보이는 심지의 약 **88%**가 되도록 비례 축소했다(+0 기준 씨앗 약 28px / 심지 약 33px). 기존 씨앗은 약 66px로 너무 컸다.

3. 착지 시 약 0.26초 동안 **`가시꽃 줄기.png` ×5 + `가시꽃 잎.png` ×5 + `가시꽃 심지.png`**가 중심에서 일제히 팍 펼쳐진다. 이는 공격 피해가 아니라 **설치 단계**다.
4. 전개 완료 후 **`가시꽃 완성본.png`**로 대기한다. `T`를 누르면 표적 위치에 가장 가까운 무장된 덫 1개가 가상 발동하며 팔이 오므라들고 파동이 나온 뒤 사라진다. `T`를 누르지 않으면 설치 수명이 끝나고 소멸한다.
5. `Q/E`로 **반경 62/80/100/125px**, 설치 대기시간 **6/7/8/9초**를 비교. 여러 덫을 연속 생성하여 설치된 덫들의 독립 동작을 확인할 수 있다(실험실 안전상 동시 최대 12개).

**원작 물리 재검증(2026-10-31):** 기존에 추가한 `rolling_on_ground` 전용 상태 및 `exp(-drag*dt)` 마찰은 **Magicraft 원작의 구현이 아니므로 폐기**했다. 원본 `Spell1012TrickMineSystem`은 일반 투척 지뢰에 `Gravity=15`, `CurrentFallSpeed=-4`, `FallingReboundForceRatio=0.33`, `Float3=±15`를 부여한다. **실제 움직임은 공통 `SpellMoveJob.TrickMine_Fall()`에서 계산**하며, 충돌 시 `CurrentFallSpeed *= -0.33*1.6`, `Speed *= 0.66`, `Float3 *= 0.66`로 처리한다. 멈춤 기준은 `abs(CurrentFallSpeed)<=0.2` 또는 `Speed<=0.2`. `Float3=15`는 `quaternion.Euler()`에 전달하는 **라디안/초** 값이며, 과거 문서의 **15도/초는 오해**였다. 결과적으로 바닥을 따라 조금씩 튀고 이동하면서 회전량이 줄어드는 구조이지 독립적인 굴림 애니메이션은 아니다.

**우리 게임과 원작의 분리:** 원작 `SpellConfig.json`의 기본 수명은 **3.5초**. 실험실에서는 강제 1.55초 지연 대신 **정지 조건 충족 시 전개**하고, 혹시 끝나지 않으면 **3.5초를 안전상 상한**으로 사용한다. 이 상한은 게임 규칙으로 확정된 것이 아니다. `64px/Unity 단위` 환산과 그림자 높이 축소도 화면 실험용이며 원작 수치가 아니다. 원작 지뢰의 종료 폭발을 가시꽃의 빠른 **전개**로 바꾸며, 전개 후 접근 발동은 별도 상태다. 원작의 적 접촉 폭발·다른 지뢰 연쇄 폭발·지형/절벽 충돌은 Test-Room에 구현하지 않았다. **씨앗 크기(심지 약 88%)와 제공된 5종 PNG는 변경하지 않았다.**

**2026-10-31 회전 방향·설치 시점 재교정:** 기존 버전은 원작의 `Float3` 회전 부호를 그대로 Godot에 넣어 **오른쪽 이동 중 반시계방향으로 역회전**했다. Godot은 Y축 아래쪽·양의 회전이 화면상 시계방향이므로 Unity의 +Z 회전과 화면상 방향을 맞추기 위해 부호를 반전했다. 또한 설치를 1.55초에 강제하던 코드를 없앴고 정지 조건 충족 시 전개하도록 고쳤다. 원작 물리 계산 이외의 장면 투영·이미지 회전과 전개가 원작과 같은 동작이라는 주장은 하지 않는다.

**정확도 및 미확정 사항:** 위 운동의 핵심 충돌 수식은 원작 ECS 공통 이동 코드 `SpellMoveJob.TrickMine_Fall`에서 확인한 그대로다. 물리 엔진의 지형/적 충돌과 Godot 렌더링, 프레임 간 보간은 원작과 동일하지 않다. 원작 복제를 검증했다고 주장하지 않으며 실제 Godot 4.6 시각 테스트가 필요하다. 원작 폭발 피해/연쇄 폭발은 의도적으로 제외. 현행 실험실에는 적이 없으므로 **T키를 적 접근 트리거로 대체**한다. 합성 `meteor_thorn` / `timed_thorn`의 본게임 로직이나 기존 `garden` 중첩·성장은 수정하지 않았다. 탄 이미지와 완성본의 중심을 맞추는 데 512x512 투명 캔버스 좌표를 그대로 사용하며, 초기 스프라이트들은 전부 교체 없이 원본을 참조한다.

## 서리검 VFX (6번)

**사용자 그림:** `assets/얼음칼.png` (512×512). 사용자가 그린 칼 이미지를 별도 재가공하지 않고 사용한다. 그림에서 **손잡이 끝(위쪽 약 x256,y20), 가드(약 y135), 칼날 끝(아래쪽 약 x256,y490)**을 구분했다. 기존 회전축 `(256,105)`는 손잡이 끝이 아니라 가드에 너무 가까웠으므로 **손잡이 맨 끝 `(256,20)`으로 변경**하고, 검기 칼끝 반경도 `385 → 470` 원본 픽셀에 맞춰 함께 수정했다. 이 좌표는 Test-Room용 그림 배치값이며 원작 Magicraft 프리팹의 정확한 피벗을 증명하는 정보는 아니다.

**움직임 레퍼런스:** 마법공예 `Spell1021MoveJob.GetCurveValue()` → `DTool.GetCurveY((0.2,0.5),(0.6,0.95),t)`의 **3차 다항식**을 사용한다. 원작의 일반 시전 `InitFlipY()`처럼 **시전할 때마다 반대 방향으로 스윙**한다. 등장 단계 0.2초, 검격 완료 진행률 80%, 퇴장 0.25초를 따른다. 원작은 `SlashTime=Scatter/360/speed_ratio`로 계산하므로 실험실은 시각 확인용 `speed_ratio=1`로 고정한다.

**VFX 레이어(개선판):** 업로드한 검 본체 / **원작 휘두르기 곡선에서 매 프레임 1.5° 이하 간격으로 보간하는 연속형 냉기 리본** / 색·투명도가 부드럽게 변하는 2중 서리 검기 / 칼날 끝을 따라 이어지는 가는 안티앨리어싱 라인 / 아주 약한 이전 칼날 잔상 / 칼날 근처에만 발생하는 적은 얼음 파편. 기존의 **프레임마다 별도 사각형을 그리던 끊긴 검기**와 큰 칼끝 점을 지양했다. 검기 잔상 수명은 약 0.17초이며 독립 PNG는 필요 없다. **히트박스·피해·상태이상 판정은 전혀 생성하지 않는다.**

**검기 폭·얼음 질감 개선(2026-10-31):** 사용자 실행 화면에서 기존 검기의 안쪽 시작 위치가 칼끝 기준 반경 **0.66~0.79**에 치우쳐 칼날 전체가 아닌 바깥쪽만 뒤따르는 것으로 확인됐다. 이제 손잡이와 가드를 제외한 실제 칼날 시작점 **(회전축 기준 y138 / 전체 칼끝 y470 = 약 0.294)**부터 칼끝 **1.0**까지 **전 구간**에 연속형 검기를 그린다. 청백색 반투명 기본 띠에 옅은 내부 결정층과 안쪽·바깥쪽 가장자리의 연속 윤곽을 합쳤으며, 칼끝의 독립적인 밝은 점은 두지 않았다. 원본 `얼음칼.png`는 수정하지 않고, 회전하는 그림 위에 작은 **투명 결정 면·얼음 균열 하이라이트**만 추가했다. 원본은 평평한 청록색 면과 밝은 외곽선이어서 얼음 결정이라기보다 마력 검처럼 읽힐 수 있다. 필요시 에셋의 내부 명암·결정 면을 추가하는 후속 아트 작업을 권장한다. **이 변경은 VFX 렌더링만** 다루며 검격 시간·피해·동결·합성·본게임에는 적용하지 않는다.

**비교 전용 +0~+3:** 시각용 원호를 150° / 180° / 240° / 240°로 두고, +3에서는 원호가 아닌 크기만 추가 비교한다. 150°·180°·240°는 마법공예 소스의 참조값이지만 **우리 게임의 강화·밸런스 수치로 확정한 것이 아니다.** 원본 유저 기획 문서에는 이름을 `얼음검`으로 표기한 부분이 있으나, 현재 독립 VFX 테스트에서는 요청에 맞춰 `서리검`을 사용한다. 내부 `frost` 공격 코드와 본게임은 수정하지 않는다.

**공유 셰이더:** 7번은 9번의 `lightning_arc.gdshader`를 새로운 개별 `ShaderMaterial` 인스턴스로 참조한다. 9번을 수정하지 않고 두 마법을 나란히 테스트할 수 있다. 프로젝트 설정은 기존 Godot 4.6 GL Compatibility를 유지한다. 과거 MIT 기반 구현을 언급한 설명은 개편 전 기록이며 현재의 주 낙뢰 코드는 CC0 기반의 셰이더 구현이다.

**검증:** GitHub 소스/참조 연결을 정적으로 확인했으며, 실제 Godot 렌더링 및 셰이더 컴파일은 로컬에서 추가 확인이 필요하다.

## 잔불 발자국 VFX v4 — 형상 자체를 교체, A/B/C 비교 (2026-10-31)

**목적:** v3에서 가장 큰 문제였던 '주황색 털뭉치/둥근 입자'를 제거한다. 기존 v3 원형 화염 GPU 파티클 3레이어를 **모두 제거**하고 **연결된 화염 몸체를 가진 쿼드 셰이더**와 **독립 생성 플립북**으로 교체했다. 사각 투명도·붉은 색감을 회귀시키지 않는 것을 목표로 한다.

**A — 마스크 + 상승 노이즈:** `shaders/ember_fire_mask.gdshader`. 3개의 서로 겹치는 물방울형 화염 줄기가 바닥에서 하나로 이어지며, 높은 부분일수록 왜곡이 증가한다. 노이즈 텍스처는 `FastNoiseLite + NoiseTexture2D`로 최초 한 번 생성해 공유한다. 2개 스케일의 노이즈가 서로 다른 속도로 상승하고, 외곽/황금색/황백색 심지가 **동일 필드의 서로 다른 임계값**을 사용해 내부가 분리된 원처럼 떠다니지 않는다.

**B — 실제 애니메이션 플립북:** `scripts/ember_fire_flipbook_builder.gd`가 **12장의 80×88 원본 프레임을 코드로 생성**, 4×3 아틀라스를 1회 캐싱한다. `shaders/ember_fire_flipbook.gdshader`가 12fps로 프레임을 재생한다. 원본 Magicraft 추출 이미지/애니메이션을 복사하지 않으며, 3갈래 연결 화염·끝부분 난수 침식·밝은 심지를 독립 알고리즘으로 제작한다.

**C — 혼합형(기본):** A의 화염 본체와 B의 낮은 강도 변형 화염을 함께 사용한다. 불꽃 부분은 **최대 두 쿼드**이고, 부수 효과인 작은 연기/불티만 별도 `GPUParticles2D` 두 개로 유지한다. 둥근 화염 본체 파티클은 사용하지 않는다. 모든 버전에서 바닥 열기는 기존 셰이더를 유지한다.

**비교 방법:** Test-Room `8`번을 선택하고 `R`로 자동 반복을 끈다. `F`를 누를 때마다 **A 마스크 → B 플립북 → C 혼합**을 순환한다(초기값 C). 클릭 시 현재 모드로 새 경로가 생성되며, 기존 설치 경로의 모드는 바뀌지 않아 화면에서 나란히 비교할 수 있다. `Q/E`는 기존 강화별 반경 **24/30/36/42px**과 수명 **1.8/2.2/2.6/3.0초**를 유지한다. `↑/↓`는 보조 불티/연기 밀도 조절용이다.

**자료 및 판단:** Federico Bellucci의 [Procedural Fire](https://blog.febucci.com/2019/05/fire-shader/), [Godot 2D Fire Mask](https://godotshaders.com/shader/2d-fire-mask/), [Anime Style Fire 2D](https://godotshaders.com/shader/anime-style-fire-2d/)의 서로 연결된 화염 마스크와 시간 흐름을 참고했다. Unity/Magicraft 원본 텍스처는 일절 반입하지 않았다.

**검증 상태:** Godot 4.6 GL Compatibility 엔진의 실제 렌더/화염 애니메이션 및 컴파일 실행 검증은 수행하지 못했다. GitHub 정적 파일 검증과 UI 1~9 및 본게임 코드 보존을 확인한다. 로컬에서는 특히 B 아틀라스 최초 생성 지연, 12fps 반복 경계, A 노이즈 준비 시점, A/B/C의 지속시간, 여러 장판 오버드로우와 FPS를 확인해야 한다.


## 잔불 발자국 VFX v5 — 산 모양 제거 (2026-10-31)

사용자 스크린샷에서 v4의 연결 화염이 불 대신 **폭과 높이만 다른 삼각형/산**으로 보이는 문제가 확인됨.

- A(마스크): 고정된 3갈래 `tongue()` 및 폭이 일정하게 좁아지는 cone 수식을 **삭제**. 시간·x에 따라 달라지는 불규칙 최고높이(crest), 큰 상승 노이즈/작은 상승 노이즈, 부서지는 상단과 움직이지 않는 바닥을 구현.

- A/B 쿼드는 높이를 88에서 72/70px로 낮춰 더 넓은 바닥 화염의 비율을 만든다. 화염 밑면은 페이드 처리해 직선 절단을 완화. C는 B 혼합 강도를 0.48→0.32로 줄인다.
- **기존 F 비교(A/B/C), 8번 경로, Q/E 크기·수명, 연기·불티, 7번 벼락, 9번 번개 아크와 본게임은 유지.**

2. 기본 공격 **별빛탄** + 보조 **공전** → Space → 중심 기준 궤도가 실제로 한 바퀴 이상 유지되는지 확인한다.

4. **꽃폭탄** + 공전 → 약 4.95초 후 공전 종료 위치에 꽃폭발이 발생하는지 확인한다.
5. **별빛탄** + 낙하 → 경고(0.40초)와 하강(0.48초) 후 원본 VFX가 나오는지 확인한다.
6. **별빛탄** + 낙하 + 공전 → 착지 위치 중심으로 공전을 시작하는지 확인한다.
7. `C`를 눌러 대기 중인 낙하와 공전 객체가 정리되는지 확인한다.

## 2단계 수정 — 마법공예 낙하 원본 참고 및 공전 예외 5종 (2026-11-01)

**이 단락이 위의 '2단계 — 낙하 + 공전' 초판 설명보다 우선한다.** 기존 '7종 원형 공전/공통 낙하 광체' 서술은 개편 전의 기록이다.

### 실제 참고한 원본 역공학 코드/보고서

- [SpellTools.cs / SpellInitialFallData](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/SpellTools.cs) 및 [坠落逆向分析.md](https://github.com/kav1982/_reverse_engineering/blob/main/%E5%9D%A0%E8%90%BD%E9%80%86%E5%90%91%E5%88%86%E6%9E%90.md): 목표점에서 탄의 방향 반대로 **2 단위** 물리고 수직 높이 **-7**에서 시작. 실제 탄체의 수평 이동과 일정 하강 속도를 함께 수행하고, 지면에 닿을 때 공격한다. 중력은 첫 낙하가 아닌 반발 과정에 사용.
- [SpellMoveJob.cs / Normal_Rotation](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/SpellMoveJob.cs): 궤도 이동 각속도는 **투사체 이동 속도 / 반경**에 비례. 공전 강화로 속도/반경 변화 시 회전 속도도 바뀌어야 한다. 이 파일의 Boomerang_Rotation 등은 별도 고유 움직임도 정의한다.
- [Spell1004LaserJob.cs](https://github.com/kav1982/_reverse_engineering/blob/main/decompiled/Assembly-CSharp/Spell1004LaserJob.cs) 및 [激光逆向分析.md](https://github.com/kav1982/_reverse_engineering/blob/main/%E6%BF%80%E5%85%89%E9%80%86%E5%90%91%E5%88%86%E6%9E%90.md): 공전 광선은 **36선분 × 10°의 고정 360° 원형 경로**를 한 번에 생성한다. 직선 빔을 회전시키는 방식이 아니다.
- 원본 Unity 3D의 **2 대 7 거리 비율**을 Godot 2D 화면에서 **수평 뒤쪽 112px / 상공 350px**의 투영으로 환산했다. 전환 시간은 VFX 시험용 0.28초 예고 + 0.50초 하강으로 임시 설정했다. **이 픽셀 수치는 원작의 정확한 화면 측정값이 아니다.**

### 낙하 — 흰 광체 대체를 제거

- 별빛탄·꽃폭탄·달빛 부메랑·블랙홀·가시꽃 덫·독 탱탱볼·화염구에서는 **원래 공격의 Node2D/스프라이트를 그 상태로 비스듬히 하강**시킨다. 착지 전에 원래 직선 이동/폭발 처리는 일시정지한다. 착지 시 같은 개체의 공격 VFX 처리를 다시 연다. **하강용 가짜 흰 구체가 원래 탄으로 변하지 않는다.**
- 얼음검·벼락·번개 아크·광선은 움직이는 별도 탄체가 없는 특수 공격이라 **착지 지점 예고 표시 후 기존 공격을 발동**한다. 이 경우 완성된 '원래 무기 자체의 낙하 애니메이션'은 아직 아니다. 단, 예전 흰 구체가 내려오는 임시 연출은 그리지 않는다.
- 낙하+메아리·낙하+갈래·낙하+공전의 기존 발사 예약 규칙은 유지한다. `C` 초기화는 미착지 하강도 취소한다.
